PROMPT 1 - WHAT WE ARE BUILDING
====================================================================

I want to build "StitchPro Studio", a browser-based embroidery digitizing
editor. A user draws shapes (or brings in pictures, SVG artwork, typed text
or existing machine files), chooses how each shape is stitched, sees the
exact needle sequence on screen, and downloads a machine embroidery file
(DST, PES, EXP, JEF, VP3, XXX).

Product rules:
- It will be a hosted web product. Designing and previewing are free;
  downloading the machine file will be paid per download (one payment
  covers every format of one design; stored designs can be downloaded
  again free). Accounts and payments come much later. For now everything
  runs locally and every download is allowed, but leave a single
  "entitled(plan)" check on the server where the paywall will go.
- The machine-file writer must only ever run on the server, never in the
  browser (a browser writer would bypass the paywall). The browser sends
  the finished needle sequence; the server writes the file.
- Everything is stored in millimetres. Inches are only a display/input
  preference. y grows downward everywhere (screen convention).
- The stitch engine and the editor must be separate, reusable packages so
  the editor can later be embedded inside another web product.
- Native design files use the extension .sps; native embroidery fonts use
  .spf.
- No sequin, bead or rhinestone features.
- I develop on Windows: every command must work in PowerShell/cmd.

Technology:
- TypeScript monorepo with npm workspaces: engine, editor, web.
- engine: pure TypeScript plus JSTS (JavaScript port of the GEOS
  computational-geometry library) for polygon operations. No DOM, no
  framework, no network, no global state - it must run in a Web Worker.
- editor: framework-free TypeScript; Canvas 2D rendering; opentype.js for
  reading font files.
- web: React + Vite app shell; jsPDF for PDFs; utif2 for TIFF pictures;
  open-licensed (SIL OFL) fonts from the @fontsource packages.
- server: Python FastAPI + uvicorn + pyembroidery (MIT licensed).
- Tests: Vitest (engine, editor), pytest (server), Playwright (browser).
- I am providing thread charts downloaded from the melco website and freely available for embroidery software. It is located in the folder /threadcharts. Please make a note of it in the docs. Here is the website. https://melco.zendesk.com/hc/en-us/articles/360027079632-Adding-and-Updating-Thread-Charts-in-DesignShop-Melco-OS-and-Bravo-OS

Hard engineering rules (keep them for every later prompt):
1. Machine-file writing stays on the server.
2. The engine stays pure: plain data in, plain data out.
3. One place for geometry: all curve math in engine/src/path.ts; all
   polygon operations (union, buffer/offset, clip, covers) in
   engine/src/geometry.ts.
4. Never recompute or redraw everything on a mouse move. Each object's
   stitches are cached by (object id, version); every change to an object
   bumps its version. Designs can reach 100,000+ stitches.
5. All editing logic lives in the editor package; the React shell only
   calls the editor's public API and re-renders when the editor says it
   changed.

Do not write code yet. Confirm the plan back to me in a short summary.

PROMPT 5 - CURVE MATH (engine/src/path.ts)
====================================================================

Implement:
- materializePath(nodes, closed, resolution = 0.4 mm): straight between
  corner nodes; a segment touching a curve node is a cubic Bezier curve
  whose control points follow Catmull-Rom spline tangents, placed one
  third of the segment length from each end. Corner nodes always stay
  sharp. Flatten curves by arc length about every 0.4 mm.
- materializeSegments: the same, one dense piece per node-to-node segment.
- materializeWidths: per-point column width, linearly interpolated by
  arc length along each segment.
- flattenBezier (quadratic and cubic) and flattenArc (SVG elliptical arc,
  following the SVG 1.1 implementation notes for endpoint-to-centre
  conversion and radius correction).
- cumulative lengths, pointAt(path, d), resamplePolyline (fixed or
  function spacing), resampleWithValues (carry widths along by linear
  interpolation), resampleKeepingCorners (always a needle point on every
  sharp corner), findCorners (vertices turning sharply; only real corner
  vertices), restartRing (rotate a closed polyline to start at the point
  nearest a given point), trimEnds (shorten/extend the ends by mm).
- douglasPeucker: the Ramer-Douglas-Peucker line simplification.
- smoothPath(nodes, closed, precision): fewest nodes that keep the line
  within `precision` mm: corners stay corner nodes; between corners use the
  fewest curve nodes found by Ramer-Douglas-Peucker with a tightening
  tolerance until the curve stays within precision; per-node widths carry
  over; unchanged if nothing is saved.
- Python-compatible round-half-to-even and floored modulo helpers.
Unit-test each with small exact cases.

PROMPT 7 - SPACING CONVENTION AND RUNNING STITCH STYLES
====================================================================

Spacing convention (important): tatami spacing is the distance between
two FORWARD rows, satin spacing between two FORWARD stitches, so
neighbouring lines are half that apart. Add sewnSpacing(settings) that
halves fillRowSpacing for tatami and laydown, and satinDensity (and
gradedEndDensity) for satin, two-rail satin and satin fill, before any
generator runs.

Running stitch (engine/src/stitchlib.ts): resample the path every
stitchLength. Styles:
- triple: start point, then for each stitch: forward, back, forward.
- sculpture: odd stitches triple, even stitches single.
- backstitch: first point, then for i >= 2: point i, point i-1; then the
  last point.
- stemstitch (a rope): len = max(0.5, stitchLength), half = max(0.1,
  stemWidth/2); for d = 0, len/2, len, ... while d + len <= total: output
  the point at d offset half to the left, then the point at d + len offset
  half to the right (normals from points 0.1 mm either side).
Raised satin: for layer l = layers-1 down to 1, a satin with width x
(1 - 0.15 l) and spacing x 2; then the normal satin.

PROMPT 8 - SATIN COLUMNS (engine/src/columns.ts)
====================================================================

Satin along a centreline with a width per node.

1. Samples: walk the centreline every spacing mm (resampleWithValues);
   at each sample the centre, the unit normal (from the neighbours) and
   the width. Graded spacing: spacing changes linearly from satinDensity
   to gradedEndDensity over the whole column.
2. Automatic spacing (satin with autoSpacing): curvature = turn angle per
   unit length, averaged over a 1 mm window (moving average); outer(d) =
   min(2.5, 1 + curvature x width/2) so spacing is measured at the OUTSIDE
   edge of curves; narrow factor = 1 for width >= 3, else
   1 + ((3 - max(width, 1)) / 2) x 0.2. step = spacing x narrow / outer.
3. Sharp bends hidden by curve nodes ("sharpenBends", before corners):
   measure the angle a-p-c with a and c at reach = clamp(0.75 width, 0.8,
   4) mm either side; a point is a bend if that angle < max(mitreBelowDeg,
   capBelowDeg) AND at least 55 % of the turn happens within reach/3; take
   the sharpest point of each run, skip existing corners; replace the
   rounded stretch (0.6 x reach either side) by the line-line
   intersection of the two sides (if it lies ahead and within 2 x reach).
   On closed paths first move the seam as far as possible from corners.
4. Corners: split the centreline into straight legs at sharp corners
   (auto mode: only corners whose angle between the sides is below
   max(mitreBelowDeg, capBelowDeg)). Per corner: dIn, dOut, mitre line
   normal = normalise(dIn + dOut). Mitre when (mode mitre and turn <= 120)
   or (mode auto and angle >= capBelowDeg); otherwise cap.
   - Rungs of each leg are square to it; within clipRadius = (width/2 +
     pull) x 4 + spacing of a corner they are clipped to their side of the
     mitre line (a half-plane test, cut at the crossing point).
   - Mitre: extend the legs to the mitre point; extension length =
     half-width x tan(turn/2) computed as half x |cross| / (1 + dot).
   - Cap: a fan of rungs round the outside: angles from the incoming to the
     outgoing outer normal, outer end at radius width/2 + pull, inner end on
     a small arc of radius min(0.5, width/4), steps = ceil(radius x |angle|
     / spacing).
   - Auto mode drops corner stitches shorter than 0.5 mm.
5. Stitches: one per rung, alternating edges (side = (i + firstSide) mod
   2), pull compensation pushes both ends out. Ragged edge: pull the edge
   point in by min(ragged(d, side), 0.9 x half-width), where
   periodic: amount x (0.5 - 0.5 cos(2 pi (d/period + side/2)));
   random: amount x mulberry32(round(d x 1000) x 2 + side) (mulberry32 is a
   seeded 32-bit pseudo-random number generator; seeds are integers, so
   designs always sew the same).
6. Stitch shortening (satin): if the end of stitch i lands closer than 0.6
   x (2 x spacing) to the end two stitches back on the same edge (and that
   one wasn't shortened), stop it 35 % of the way across instead.
7. Auto split: a stitch longer than splitLength gets n - 1 extra points,
   n = ceil(len / (0.8 x splitLength)), each shifted by
   ((i x 0.6180339887498949) mod 1 - 0.5) x 0.5/n - a golden-ratio
   (Weyl) low-discrepancy sequence so splits never line up.
8. Entry/exit side: if the last stitch ends on the wrong side, add one
   stitch back across.
Zigzag: same rungs, spacing zigzagSpacing/2, no satin-only steps.
E stitch: per rung output base, tip, base (eFlip swaps the edges), spacing
eSpacing.
Test straight, tapered, mitred, capped and heart-shaped satins.

PROMPT 9 - TWO-RAIL SATIN AND THE COLUMN TOOL
====================================================================

Two-rail satin: align rail 2 so its ends are nearest rail 1's ends; walk
both rails by the same FRACTION of their length (arc-length
parameterisation), spacing measured on the longer rail; stitches alternate
rails; pull compensation and ragged edge as in prompt 8.
Column tool objects (pairedRails): node i of rail 1 pairs with node i of
rail 2; each pair is a rung; sew piece by piece between rungs with steps =
max(1, round(longer piece length / spacing)), so the stitch angle turns
smoothly from rung to rung.
Stitch angle lines on these: for each line, intersect the infinite line
with each rail polyline (line-segment intersection; take the crossing
nearest the line's middle); a line crossing both rails becomes an extra
rung; merge with the Column's own rungs (own rungs win when two are within
0.05 mm or would cross); cut both rails at the rungs (sub-paths by arc
length) and sew with the Column method.
Column shortening (columnShortening, default OFF): the shortening rule of
prompt 8, using the far rail point of each rung as the "other end".
Underlay for rails: rungs every step along the longer rail, inset at both
ends (never under 0.2 mm), margins at the start/end; edge run = down one
side, back the other; zigzag = across rungs then a centre run back (or a
second crossing zigzag); slant via underlayZigzagAngle.

PROMPT 10 - TATAMI FILL (engine/src/fill.ts)
====================================================================

1. Rotate the shape (with holes) by -fillAngle so rows are horizontal.
2. Sections by scanline polygon filling with the even-odd rule: rows every
   spacing (after halving) from the top; nudge a row 1e-6 mm off any
   horizontal edge; a row's span joins the section above only if they
   overlap one-to-one, else a new section starts.
3. Each section can be sewn 4 ways (top-down or bottom-up x first row left
   or right); the first (forward, left to right) wins ties. Pull
   compensation extends row ends.
4. Needle points on a shared grid fillStitchLength apart, shifted per row
   (row number counted from y = 0); row ends always sewn; grid points
   within a quarter stitch of an end skipped. Row phase per pattern:
   thirds row mod 3 / 3 (default); quarters row mod 4 / 4; fifths
   ((row mod 5) x 2 mod 5) / 5; brick row mod 2 / 2; random = a repeatable
   integer hash of the row; diagonal = offsets A 0.3 / B 0.6 alternating
   (frac(floor(row/2) x (A+B) + (odd ? A : 0))); diagonal-left 0.7 / 0.4;
   chevron eighths 0,1,2,3,4,3,2,1; herringbone 0,2,4,6,0,6,4,2; basket
   0,0,0,0,4,4,4,4; embossed patterns (diamonds, waves, zigzag, stripes,
   scales) = thirds plus extra needle points where the row crosses a carved
   shape of one repeat embossWidth x embossHeight (diamonds: diagonal
   lines; waves: a sine; zigzag: a triangle wave; stripes: vertical lines;
   scales: circle arcs in half-height bands, alternate bands shifted half a
   repeat); a carved point replaces a grid point beside it. Stagger off =
   each row divided evenly from its own start.
5. Travel between sections, staying inside: straight when the segment is
   covered, otherwise detour along the edge it hits the shorter way round
   (recursive, depth 16). When both ends lie on the same edge and walking
   it is at most twice as long, walk the edge.
6. Travel on edge (default on, top layer): keep a list of sewn section
   outlines; try, in order, walking the edge inset 0.3 mm the short way,
   the long way, then straight if covered; accept the first whose length
   on top of sewn rows (sampled every 0.25 mm, point-in-polygon) is <=
   max(1, 2 x row spacing); otherwise make a jump marked by repeating the
   landing point twice. Between different rings, walk to the closest
   point, hop across, walk on.
7. Order: greedy nearest section, with a cost of distance + 1000 if the
   move lands on sewn rows + distance to the next section + 500 if that
   next move would cross sewn rows. For fills of up to 10 sections, first
   try a depth-first search with backtracking (budget 400 steps, at most 6
   candidates per step, nearest first) for an order where every move can
   travel off sewn rows, the section nearest the exit point last.
8. A row-to-row move longer than 2 row spacings that is longer than 2
   stitches or leaves the shape travels instead.
9. Entry/exit points: start at the entry, finish at the exit (travel there
   if more than 0.3 mm away). Separate pieces of a fill: each sewn whole,
   nearest next, the one with the exit last.
Underlay pass for tatami: the same generator at fillAngle + angle, row
spacing max(0.5, underlaySpacing), stitch 4.0, no stagger, pull
compensation = -underlayInset.
Fill zigzag underlay: one point per row on alternate sides, long stitches
split at 7 mm; double = second pass on the other ends. Fill edge run:
running stitch round the outline and holes inset underlayInset.


====================================================================
PROMPT 11 - TURNING FILLS (engine/src/turning.ts)
====================================================================

Stitch angle lines across a fill: one sets the fill angle; two or more on
tatami or satin fill turn the rows.
- Order the lines into a chain (start with the line whose middle is
  farthest from the others, then nearest-neighbour), and flip lines so
  consecutive ones point the same way.
- Rows between neighbouring lines: max(1, round(largest end-to-end
  distance / spacing)). Row line at row number s: linear interpolation of
  the two lines' end points; beyond the first/last line, parallel lines
  stepping away.
- toLocal(p): find the row s whose line passes through p by bisection
  (root finding on the sign of the cross product, 60 iterations, 1e-7);
  x = projection on the row direction, y = s x spacing. No sign change =
  the lines cross: give up.
- Map the shape into this straightened frame, check orientation (signed
  area via the shoelace formula; a flipped sign means the warp folds: give
  up), run the ordinary tatami there with angle 0, map stitches back.
- Giving up = sew with the single fill angle.


====================================================================
PROMPT 12 - THE OTHER FILLS
====================================================================

- Satin fill: tatami rows at satinDensity spacing with no needle points
  between row ends, auto split on, turning like tatami.
- Radial fill (outline stitch): rings inset by outlineSpacing each time
  (polygon offset), each started at the vertex nearest the last ring's end;
  pinched pieces finished one at a time, nearest first; rings round holes
  last; ripple = sew from the centre out.
- Contour: find the two extreme points of the outline along the fill
  angle (on flat ends, the one nearest the middle); split the outline into
  two sides; resample each to 201 points; rows = ceil(widest gap / row
  spacing); row k = linear interpolation of the two sides at k/rows;
  alternate direction; resample each row by stitch length.
- Stipple: grid of cells (spacing c = max(0.8, stippleSpacing)) inside the
  shape shrunk by c/2; a maze by randomized depth-first search (a random
  spanning tree, mulberry32 with seed 7); walk the tour round the tree
  offset a quarter cell to the right of each step; smooth with three
  passes of Chaikin's corner-cutting algorithm (points at 1/4 and 3/4 of
  each segment); resample by stitch length.
- Cross stitch: grid of crossSize squares starting at 0 mm (shared by the
  design); a square counts if its 4 corners and centre lie inside the
  shape grown by 0.15 x size; per row, runs of squares: "/" strokes going
  right, then "\" strokes coming back; crossDouble sews each stroke twice.
- Motif line: a motif is points in a unit box (x 0..1 along, y -0.5..0.5
  across, from (0,0) to (1,0)); repeat it along the path scaled to
  motifLength x motifWidth, stretching slightly so a whole number fits,
  with motifGap of running stitch between. Built-in motifs: wave, scallop,
  rickrack, diamond, leaf, cross, loop, triple.
- Motif fill: rows of motifs at the fill angle, motifRowSpacing apart,
  every other row shifted by motifRowOffset, every other motif raised by
  motifColumnOffset x row spacing, optional alternate motif scaled by
  motif2Scale; only motifs wholly inside are sewn.
- Laydown: tatami (no stagger) at its spacing and length; with two layers,
  a second pass at fillAngle + laydownAngle2 starting where the first
  ended; no underlay.


====================================================================
PROMPT 13 - UNDERLAY AND HOW ONE OBJECT IS SEWN
====================================================================

Underlay only on tatami, satin fill, satin and two-rail/column, never
under 2 mm wide (column: average width; fill: 2 x area / perimeter).
Automatic: column under 4 mm -> edge run; wider -> edge run + zigzag; fill
under 100 mm2 -> edge run; larger -> edge run + tatami. Up to two layers
(layer 2 uses the underlay2 settings); each starts where the last ended.
Column edge run: down one edge inset, back up the other. Column zigzag:
zigzag down (spacing per edge), centre run back; margins trim the ends.
Lettering under 5 mm cap height: no underlay.

Sewing one object: underlay layers, then top stitching, joined inside the
object. A move that would leave a fill, or is longer than 7.5 mm, travels
along the edge just inside (or straight under the fill when travel on edge
is off); in columns it runs back along the middle; travel stitches 2.5 mm.
Closed outlines start at their entry point; open lines sew from the end
nearer their entry.

"What an object covers" (objectArea): an area's outline and holes, or a
column's band (nest its edge rings; the outer edge is the shell);
open lines and manual stitches cover nothing.

PROMPT 14 - EXPORT PLAN (engine/src/export.ts)
====================================================================

buildExportPlan(doc, stitchesOf) -> { name, threads [{color, name, brand,
code}], commands [[stitch|jump|trim|stop|color_change, x, y]], autoJump,
maxStitch, trimJumps }.
- Split each object into runs at connectors (with auto trim): areas: a
  move longer than the trim distance crossing open fabric, or a jump mark;
  running/motif/manual: a move longer than the longest stitch. Columns are
  one run. Drop stitches shorter than minStitch (keep each run's ends).
- Between runs: new colour -> tie-off, trim, colour change, jump, tie-in.
  Farther than trimThreshold -> tie-off, trim, jump, tie-in, UNLESS
  (a) all but trimThreshold mm of the straight way lies under the next up
  to 8 same-colour objects still to come (check with the rasterized covers
  test, sampling every 0.2 mm) -> sew it as 2.5 mm stitches; or (b) closest
  join: the next object comes within joinDistance of where the last ended
  -> step to its nearest stitch and run inside it to its entry. Otherwise
  run straight on (auto trim off: a jump).
- stopAfter -> stop. hoopOut -> tie-off, trim, jump to the point, stop.
- Design starts with jump, stitch, tie-in; ends with tie-off and trim.
  Tie-in/off = two stitches 0.7 mm along the run and back.
- Also produce "machine marks" for the canvas: start, end, tie-in,
  tie-off, trim, stop, hoop out, colour change, travel run (with its path).
Closest join in the editor (on every commit): an object with autoEntry
starts at its point nearest the previous same-colour object's exit when
within joinDistance; a row fill's exit moves toward the next object.

====================================================================
PROMPT 21 - AUTO-DIGITIZER (engine/src/autodigitize.ts)
====================================================================

Turn a TrueType letter outline into draft satin columns:
1. Scale to a 20 mm capital height; nest the outline rings into shapes.
2. Rasterize each shape at 0.08 mm pixels (3 px padding).
3. Exact Euclidean distance transform (the Felzenszwalb-Huttenlocher
   lower-envelope algorithm, run on columns then rows).
4. Skeletonize with the Zhang-Suen thinning algorithm, then delete
   "staircase" corner pixels.
5. Trace the skeleton into a graph: nodes = clusters of pixels whose
   neighbour count is not 2; edges = pixel runs between nodes; plain loops
   = cycles.
6. Prune spurs: up to 4 passes removing a dead-end edge at a junction
   (degree >= 3) shorter than max(4, 1.3 x the junction's distance value)
   pixels (0.6 for serif fonts).
7. Chain edges into strokes: pass straight through 2-way nodes; at
   junctions pair the edge ends whose directions are most opposite (dot <
   -0.6), each used once.
8. Smooth each stroke (moving average of 5); width at each point = 2 x the
   distance value (minus half a pixel) x 0.08 mm.
9. Split strokes turning sharper than 75 degrees (measured over 0.75 x
   width); trim the rounded bit at a cut; the piece ending at a corner runs
   on to the letter's edge; at V corners sharper than 100 degrees both do;
   free ends run straight on to the edge.
10. Each stroke: Ramer-Douglas-Peucker simplification (0.06 mm), then
    curve/corner nodes, node widths from the nearest measured width; open
    strokes become Columns (paired rails half the width either side,
    widened at turns by 1 / cos, at most x 2); closed strokes stay satins.
11. Small blobs (dots): principal component analysis (the covariance
    principal axis) of the outline; one short column along it, as wide as
    the blob at each step. A blob with a hole: a tatami fill.
12. Sew strokes nearest-first, each from its nearer end.
Drafts are meant to be fixed by hand in the font editor.

PROMPT 22 - EDITING TOOLS ON SHAPES
====================================================================

- Knockout overlaps: the selected objects cut away the parts of earlier
  objects under them. Cutter area = outline (fills) or band (satins);
  ignore cutters narrower than 2 mm (region width). Dense area fills:
  polygon difference with the cutters shrunk by an overlap of 1 mm; drop
  pieces narrower than 1 mm. Satins: cutColumn (sample the middle every
  0.25 mm; keep runs of samples outside the cutter, at least the minimum
  length; rebuild each run as a satin or two-rail piece). Open stitches
  are left as background.
- Partial applique: a later applique piece's fabric outline cuts the
  earlier piece's cover satin (cutColumn).
- Cut (Knife): a cut line; areas split exactly (polygonize the outline
  noded with the line), pieces ordered nearest-first from the entry with
  the exit piece last; columns/lines cut by the line thickened 0.13 mm and
  their ends extended back to the line by ray-segment intersection
  (within 0.76 mm); slivers under 0.3 mm dropped; manual and hand-edited
  objects not cut.
- Weld: union of the selected objects' areas into new objects with the
  first object's settings (a non-area stitch becomes tatami).
- Fill holes: each hole becomes a new object with the same settings,
  grown by an overlap margin (default 0.3 mm).
- Laydown: union of the design's areas and its lines (each line as a band 0.75 mm either side)
  grown by an offset (default 2 mm), or a box, or an ellipse through the
  box corners; a laydown object sewn first.
- Auto applique: placement run + stop (or hoop out), tack-down (E stitch
  pointing in, zigzag or run) + stop, cover satin; grouped.
- Hoop out: after an object, cut, move to a point, stop; shown as an
  orange block in the sequence list.
